# Nexura — план до первой версии 0.1.0

## Приоритет релиза

Первая версия — стабильный мессенджер. Голосовые и видеозвонки не входят в MVP и не должны отображаться как доступная функция. Код звонков можно оставить вне пользовательского сценария до отдельного этапа; не подключать его к основному интерфейсу и не тратить на него время релиза.

## P0 — постоянный вход и доступ без VPN

- Сохранение access/refresh token только в Android Keystore-backed encrypted storage.
- Восстановление сессии при запуске; обновление access token по refresh token до загрузки приватных данных.
- Не сбрасывать локальную сессию при временной сетевой ошибке, тайм-ауте или недоступности Supabase. Выходить только по явному действию пользователя или подтверждённой невалидности refresh token.
- Защитить обновление refresh token от гонок и повторно использовать уже обновлённую сессию.
- Сетевой маршрут к Supabase: системный DNS + независимые DoH-резолверы; TLS/SNI и проверку сертификата не отключать.
- Различать DNS-ошибку, TLS/сетевую недоступность, HTTP 401/403 и ошибки самого Supabase. Не маскировать их одним сообщением.
- Если DoH не помогает, проверить доступность Supabase по HTTPS из сетей оператора и Wi‑Fi. Если блокируется сам домен/маршрут, подготовить собственный HTTPS API-прокси на отдельном домене; не вшивать секреты в APK.

**Критерий готовности:** вход и восстановление уже созданной сессии работают без VPN на Wi‑Fi и мобильной сети; временное отсутствие интернета не выбрасывает пользователя из аккаунта; после восстановления сети приложение обновляет данные.

## P1 — обязательные функции мессенджера

1. Регистрация, вход, выход и восстановление доступа.
2. Профиль: имя пользователя, имя, аватар.
3. Поиск пользователей и создание личного чата.
4. Создание групп, добавление/удаление участников, корректные права доступа.
5. Отправка и получение текстовых сообщений без дублей и потери.
6. Доставка/ошибка/ожидание отправки; локальная очередь исходящих сообщений с повторной отправкой.
7. История сообщений, пагинация, кэш и синхронизация после возвращения сети.
8. Фотографии и файлы — только после надёжной работы текстовых сообщений.
9. Push-уведомления и переход из уведомления в нужный чат.
10. E2EE: проверка создания ключей, обмена ключами, восстановления устройства и понятная индикация ошибок. Не заявлять «защищено», если ключи не опубликованы или не восстановлены.

## P2 — стабильность и безопасность

- Проверить RLS-политики Supabase для профилей, чатов, участников, сообщений, вложений и push-токенов.
- Проверить, что пользователь не может читать/изменять чужие чаты и сообщения через прямые REST-запросы.
- Устранить дубли участников и сообщений, UUID/типовые ошибки и некорректные состояния пустых профилей.
- Обрабатывать истёкшие ссылки на вложения, повторную загрузку и сетевые тайм-ауты.
- Проверить отсутствие секретного service-role ключа в APK и логах.
- Добавить журнал диагностики без паролей, токенов, содержимого сообщений и приватных ключей.

## P3 — тестирование перед публикацией

Обязательная матрица:
- Honor 10i / Android и ещё одно Android-устройство.
- Wi‑Fi без VPN; мобильная сеть без VPN; смена Wi‑Fi ↔ мобильная сеть.
- Холодный запуск, перезапуск телефона, принудительное закрытие приложения.
- Сессия после 1, 7 и 30 дней; истёкший access token; обновление refresh token.
- Кратковременный офлайн и восстановление сети.
- Два аккаунта на двух устройствах: регистрация, поиск, личный чат, обмен сообщениями в обе стороны.
- Создание группы, приглашение участников, выход участника.
- Push при закрытом приложении и переход в нужный чат.
- Проверка очереди сообщений и отсутствия дублей после повторного подключения.

## P4 — выпуск 0.1.0

- Только после прохождения P0–P3 собрать подписанный release APK.
- Проверить установку поверх предыдущей версии и чистую установку.
- Зафиксировать номер версии, список известных ограничений и резервную копию backend-конфигурации.
- Публиковать APK только после проверки SHA-256 и фактической установки на устройстве.

## Что сознательно отложено

- Голосовые и видеозвонки.
- Демонстрация сложных дополнительных функций до стабилизации базовых чатов.
- Полировка второстепенных экранов, пока остаются ошибки входа, сети, сообщений или групп.

## Текущая техническая отправная точка

В рабочей ветке уже присутствуют зашифрованное локальное хранилище токенов, восстановление сессии, сериализация refresh-запросов и DNS-over-HTTPS fallback для Supabase. Это отправная точка, а не доказательство доступности сервиса без VPN: обязательны реальные проверки на разных сетях и устройствах.
