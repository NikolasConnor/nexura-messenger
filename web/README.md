# Nexura Messenger Web

Веб-клиент Nexura Messenger. Публичный адрес:

`https://nikolasconnor.github.io/nexura-messenger/app/`

Веб-клиент использует существующий проект Supabase и общий криптографический протокол Nexura. Он развивается отдельно от Android-приложения, но должен сохранять совместимость по функциям, данным и визуальному языку.

## Уже реализовано в коде

### Аккаунт и профиль
- Вход и регистрация по email и паролю через Supabase Auth.
- Вход через Google OAuth.
- Восстановление браузерной сессии.
- Профиль, username, аватар, описание и возраст.
- Обложка профиля, фотографии, истории и каталог пользователей.
- Публикации, лайки и комментарии.

### Переписки
- Список личных и групповых чатов, создание групп и поиск людей.
- Загрузка истории сообщений и обновление через Supabase Realtime.
- Отправка текста в поддерживаемых режимах чата.
- Ответы, реакции, редактирование личных сообщений, удаление, закрепление, пересылка и сохранение в «Избранное».
- Отложенная отправка с локальной зашифрованной очередью браузера.
- Вложения, голосовая запись и воспроизведение, расшифровка и повторное шифрование медиа для получателей.
- Галерея материалов чата, поиск, оформление и режимы истории.
- Индикаторы набора, присутствия и прочтения там, где это разрешено настройками.

### Звонки и безопасность
- Интеграция LiveKit для аудио/видеозвонков.
- Общий Rust/vodozemac Olm-криптомодуль в WebAssembly.
- Браузерное хранилище криптосостояния: IndexedDB и неэкспортируемый AES-GCM ключ WebCrypto.
- Регистрация браузерного E2EE-устройства, управление устройствами и отзыв.
- Зашифрованная резервная копия состояния веб-устройства и восстановление по коду.
- Настройки приватности, блокировки и уведомлений.

## Известные отличия от Android, которые нужно закрыть для полной паритетности

- **Телефонная авторизация по SMS:** в текущей веб-форме есть email/пароль и Google OAuth; телефонный OTP-поток Android ещё не перенесён.
- **Контакты устройства:** каталог Nexura есть, но импорт телефонной книги Android не эквивалентен вебу. Для браузеров потребуется поддерживаемый Contact Picker API и явное разрешение пользователя; там, где API отсутствует, останется ручной поиск.
- **Push при закрытом браузере:** сейчас интерфейс уведомлений сообщает о поддержке уведомлений, пока веб-клиент открыт. Фоновый Web Push ещё не реализован.
- **Расшифровка голосовых:** запись и воспроизведение голосовых сообщений есть; встроенная локальная Whisper-расшифровка Android пока не перенесена в браузер.
- **Совместимость E2EE:** наличие браузерного криптографического кода не заменяет проверку совместимости Android ↔ Web. Нельзя ослаблять проверки, включать plaintext fallback или считать сквозное шифрование подтверждённым без интеграционных тестов.
- **Проверка браузеров и адаптивности:** требуется отдельная регрессия на desktop и мобильных браузерах, включая сценарии пустого чата, загрузки файлов, звонков и восстановления сессии.

Этот список является рабочим аудитом, а не заявлением, что все перечисленные функции уже прошли полноценное тестирование.

## Сборка локально

Требуются Node.js 22, Rust stable, цель wasm32 и wasm-pack:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build crypto-wasm --target web --out-dir ../web/src/crypto/pkg
cd web
npm install --legacy-peer-deps
npm run build
```

CI дополнительно запускает тесты зашифрованной резервной копии и сборку Vite.

## Безопасность

- В браузере используется только Supabase publishable key. Service-role/secret keys запрещены.
- Не добавлять plaintext fallback для сообщений, медиа или резервных копий.
- Не менять существующие таблицы, RLS-политики и Edge Functions ради визуальной паритетности.
- Перед включением или изменением E2EE-потоков обязательны тесты протокола, восстановления и совместимости Android ↔ Web.
- Все действия с приватными данными должны оставаться ограничены текущей сессией и существующими политиками Supabase.
